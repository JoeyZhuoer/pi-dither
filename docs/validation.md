# Pi Dither validation

Target: Pi Dither 0.4.0, core Pi 0.85.1, pi-subagents 0.69.0, Node.js 22.23.2, Apple Silicon/macOS. This is not certification of every Pi feature, platform or terminal.

## Plain background and installed packages (unreleased release artifact; source on `main`)

The animated background pattern is removed: the old backdrop module, canvas, motion preference and pause control are gone, and aggregated fleet activity is still computed and exposed as `#desktop[data-activity]` for the Activity window. In its place the appearance is user-controlled from the **Appearance** window: a theme (chrome) colour, a ground colour and an image picker, each with its own default. The photo is downscaled, stored locally and rendered as the **point-cloud background**: sampled cover-fit at one cell per CSS pixel, decimated into at most **800,000** points (2px dots written into a reused ImageData buffer) packed as `x, y, z, r, g, b, a`, and drawn with the reference field's spring plus a signed `1/(1+d)²` force windowed by `(1 − d/480)²` so it dies exactly at a 480px radius, with the per-pixel stiffness capped at 1.5 and the step damped by `1 + k` so the gather converges instead of oscillating — **Cloud pointer** selects Push (−100, the reference default) or Pull (+40) — with colour/alpha easing, a small depth parallax drawn centred on the canvas with Y-up cloud space (regression guard: the fixture and the native check both assert the cloud's ink centroid sits on the canvas centre, and the native spring-back check pins the pointer outside for both samples so the parallax is off in both) and a fixed 800,000-slot typed-array pool (~32 MB with inverse speeds and the swatch cache) whose surplus points fade to alpha −1: the pool carries inverse speeds and a packed-pixel swatch cache, the cloud is built straight into one Float32Array, the step skips dots that sit exactly on their target, and the controller parks once a step reports only sub-pixel motion (measured 771k points at 2px, 1440×900 across runs: 35 ms cloud build once, 8.2–8.6 ms step and 7.8–8.0 ms draw per physics frame, 12.8–13.9 ms for a realistic drag frame, 0 ms while parked; the 1px numbers were 6.7 ms step, 6.2 ms draw, 11.8 ms drag, and 6.1 ms at 386k, 2.8 ms at 193k). The site's perspective tilt is off by default (`CLOUD_PARALLAX = 0`) because it moved every dot on the canvas, far ones included, on each mouse move; a regression test asserts a pointer can only change pixels within CLOUD_RADIUS, and the fixtures check a box beyond the radius is pixel-identical in both force directions. That is the only background-pointer interaction; leaving the window drops the force and the cloud springs home. Unit tests cover colour normalization, one-cell-per-CSS-pixel sampling with the large-window bound, ordered-dither point selection, cloud decimation/centring/photo colours, the exact 1/speed easing, both force signs, the windowed monotone decay that reaches exactly zero at the radius, the stiffness cap, the attracting (non-oscillating) gather fixed point, the settled state, surplus fade-out, parallax drawing and storage/migration guards (including the legacy photo-mode keys); the Chromium fixture and the native WKWebView smoke change both colours, feed a synthetic photo through the real file input, verify the centred point cloud grows, observe the pointer displacing the points near the cursor while a box beyond the radius is unchanged in both force directions (compared by ink count and centroid: with 2px dots a few hundred boundary pixels of that box still flip on their own as the cloud settles sub-pixel, so the guard is statistical by design), then its return to the home shape, switch push/pull, and confirm removal and both resets clear/restore storage. Laptop motion (`desktop/public/motion.js`, off by default at `pi-desktop:motion:v1`) turns accelerometer samples into cloud physics and is covered on its own: mode normalisation and persistence, provider discovery for the native host, the browser fallback and none, m/s² to g conversion, the low-passed gravity direction, tilt and lag from synthetic samples, the equivalence of a sustained push and a tilt, spikes raising the shake level (including the host's between-sample peak), the damped sway spring converging, overshooting and returning to rest, the first sample after enabling becoming the baseline so motion never jumps, re-zero re-deriving the current target so a parked loop springs level again, tilt mode leaning without shaking, exact zero sway and shake while off, late host injection being picked up on the next switch-on, a zero-magnitude sample being ignored instead of normalised into a fake direction, and the measured (never assumed) sample rate. The Chromium fixture covers the same path end to end: motion off by default, an honest status line (`WAITING`, never a fabricated rate), a late `window.__piDitherMotionHost` picked up on switch-on, a stream of tilted samples leaning the whole cloud, a shake rearranging it, re-zero returning it to level, and off settling it back onto its home centre (centroid within half a pixel; the pixel count is compared with a 1% tolerance because 2px dots make rounding boundary pixels sensitive while the cloud finishes settling). With motion off the step is the same maths as before the feature existed, pinned exactly by a unit test.

The optional extra particle field (off/sparse/normal/dense) is covered by its own tests: deterministic creation, bounded speed/edges, elastic collisions with flash ageing, link/draw rules and a clean clear when switched off; it has no pointer interaction. The top-right **⚙** window chooser lists every window, remembers which ones keep a bottom-bar button (less frequent windows start out) and opens any window directly; every window remains in the Windows menu. No upload, network request or animated backdrop is involved, and the one-shot window-layout reset leaves colour, cloud pointer and photo untouched.

**Reasoning left the conversation.** Agent windows render only the answer — the old in-window reasoning block is gone — and a **Thinking** panel on the right rail streams the selected agent's reasoning: `LIVE`/`IDLE`/`OFFLINE` marker, subject line with agent, kind and model, the stream body, and a `FOLLOW` toggle. `pi-desktop:thinking:v1` stores `{ visible, follow }`, both true by default, and the **⚙** dialog gained a Thinking panel row. Verified in the Chromium fixture (`npm run test:browser`), `npm test` (145/145) and `npm run test:webkit` (390 and 1440): the panel is on the rail above the usage chart and visible by default with its settings row ticked; no conversation renders reasoning content or a "Thinking" expander; the empty state is one of the four honest texts; a state push streams the agent's reasoning into the panel, and the next push replaces it in place instead of piling up; selecting a child retargets both the subject and the content, proven with distinguishable child text; a child whose model reports `reasoning: false` shows that instead of stale text; a stream longer than the character cap keeps the newest text, drops the head, and says `TRIMMED / n EARLIER CHARS`; `FOLLOW` toggles, states its state, and persists independently of visibility; the settings row hides the panel, `Show` brings it back and closes the dialog; and after a full page reload the panel returns with its stored choices while no conversation shows reasoning.

The main agent now loads packages the same way normal Pi does: global profile `packages` (for example pi-web-search, pi-atelier and pi-subagents) are discovered through the resource loader, so their tools, commands and skills are available; the bundled pi-subagents copy is added only when the profile does not configure its own, so it never loads twice. Project `.pi` resources remain untrusted, subagent windows stay on their built-in read-only tools with no extensions, `PI_OFFLINE=1` means missing packages are never installed, and the desktop never edits Pi settings. A broken package is reported in the Tools status instead of failing startup. Verified with extension unit tests (profile-provided vs bundled fallback, escaping entries rejected, project untrusted), the installed-Pi RPC regression (a throwing profile extension is discovered and reported, the project copy is not), and a real-profile run that loaded `web_search`, `url_context` and the pi-subagents tools plus package commands. No provider prompt or paid call was used. See [feature audit](native-feature-audit.md).

## Terminal preservation boundary

Production code imports only public Pi APIs. It registers one local UI command and notification-only session/model hooks. It does not register tools, override the editor/footer, transform prompts/messages, touch credentials/settings/session files, intercept raw input, replace trust decisions, or run shell commands. Only the test harness executes a harmless shell fixture.

The local launcher disables ambient extensions to keep this release core-only. It retains normal core trust flow and persistence unless the user passes an explicit core flag. No global Pi installation or settings change is required.

## Not yet certified

- Live provider streaming, billing, retries, compaction, or steering/follow-up cancellation under a live model.
- Clipboard images, IME, external editors, assistive technology, or every configured keybinding.
- Exhaustive session import/export/fork/tree and trust-cross-cwd regressions.
- Every terminal emulator, platform, or third-party extension.
- Behavior after an upgrade beyond Pi 0.85.1. Fullscreen remains Pi's experimental mode.

These behaviors remain core-owned, but keeping ownership unchanged is not a substitute for testing them.
